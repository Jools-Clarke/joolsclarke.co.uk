# How the site works

A tour of how pages get built, where everything lives, and why it's done
this way. For the options each building block takes, see
[components.md](components.md). For everyday jobs, see the
[README](../README.md).

## The big picture

```
_data/*.yml ─────────┐   (content: me, publications, links, projects,
                     │    conferences, gallery, media)
page front matter ───┤
                     ├──> _layouts/default.html ──> _site/…/index.html
_includes/*.html ────┘      (shell: head, banner,
 (building blocks)           header, footer)
```

GitHub Pages runs Jekyll on every push and publishes the result. Every page
is **front matter** (settings between `---` lines) plus a body that is plain
HTML (or Markdown) with a few `{% include … %}` building blocks. The
**layout** wraps it in the shared shell. Anything that's a list (papers,
links, conferences, gallery) lives in **`_data/`** and is looped over, so
adding one is a few lines of YAML and it shows up everywhere it's needed.

## Decisions, and why

**GitHub Pages builds the site itself (no GitHub Action).** Nothing to
maintain. The catch is that GitHub uses its own pinned Jekyll (3.10) and only
[approved plugins](https://pages.github.com/versions/). The `Gemfile` uses
the `github-pages` gem so a local build uses exactly the same versions:
if `scripts/check.sh` passes, the live build will too.

**No plugins.** `sitemap.xml`, `robots.txt` and `llms.txt` are short Liquid
templates in the site root, so they're easy to read and change.
`theme: null` stops GitHub adding its default theme's CSS.

**One CSS file, split into pieces for editing.** `assets/css/site.css` just
`{% include %}`s each file in `_includes/css/`, so visitors download one small
stylesheet but each building block's styles sit in their own file
(`card.html` ↔ `css/card.css`). Plain CSS, no Sass: GitHub's old Sass
compiler chokes on some modern CSS.

**Colours are CSS variables.** Light values on `:root`, dark ones on
`[data-theme="dark"]`, all in `_includes/css/base.css`. A tiny script in the
`<head>` picks the theme before the page draws, so there's no flash of the
wrong colours.

**Previews instead of originals.** Posters are 5,000+ px and up to 8 MB;
PDFs up to 5 MB. `scripts/thumbnails.sh` makes an ~800 px WebP of every
image and of page 1 of every PDF (40 to 180 KB each) and records their size,
dimensions and page count in `_data/media.yml` (turning phone photos the
right way up on the way). `img.html` and
`file-card.html` look files up there automatically, set `width`/`height` so
the page doesn't jump about while loading, and lazy-load anything below the
fold. Originals are only fetched when someone clicks. The previews are
committed because GitHub Pages can't run image tools.

**Content is in the HTML, not added by JavaScript.** The conference list,
gallery and cards are all plain HTML from the templates. Scripts only add
behaviour (map, pop-up, theme). Search engines, AI assistants, and people
with JavaScript off all get the full content.

**Written for search engines and AI assistants too.** Every page has a
title, description, canonical URL and link-preview tags (`head.html`); the
homepage has JSON-LD saying who I am and linking my profiles
(`schema.html`); `llms.txt` is a plain-text summary of everything, built from
the same data; `sitemap.xml` leaves out redirects, QR duplicates and
`noindex` pages by itself. QR pages point search engines at the real page
with `canonical:` so they don't count as duplicates.

**No `mailto:` links.** Email addresses copy themselves to the clipboard
when clicked, with a little "Email address copied" pop-up (link text to
`#copy`, or give a card `copy:`). Hardly anyone has a mail app set up to
open from a link.

**Every link is a site path** (`/perturb/`, `/ccc/logo.png`), never
`https://joolsclarke.co.uk/...` or `raw.githubusercontent.com/...`. So
`localhost` shows your local files, and moving things can't silently break
the live site. `scripts/check.sh` enforces this.

**Old addresses keep working.** `/qr/`, `/qr1/`, `/qr2/`, the PDFs they link to,
and the `perturb/perturb-c_*` redirects are printed on posters and slides.

## Things that trip people up

- `_config.yml` is only read when Jekyll starts: restart `scripts/serve.sh`.
- Front matter set in a *layout* (e.g. `redirect.html`) is not visible as
  `page.something`; set things like `sitemap: false` on the page itself or
  handle them in `head.html`/`sitemap.xml` (as done for `redirect_to`).
- Liquid `assign` variables are global, even inside includes. The includes
  use prefixed names (`card_…`, `tile_…`, `img_…`) so they don't overwrite
  each other's variables.
- In Markdown pages, keep `{% include %}` lines on their own with a blank
  line either side.
- Don't put links inside a card's `text`: the whole card is already a link.
- Analytics only loads in the production build, so local visits aren't counted.
